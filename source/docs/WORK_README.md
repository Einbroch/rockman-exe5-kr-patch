## 텍스트 아카이브 모집단

1. `tools/scan_text_archives.py` — u32 리터럴(**모든 바이트 오프셋**, bit31=압축 표시 가능)이 가리키고
   경계표(`values[0]`==표 바이트 수, 오름차순)가 있는 곳. 블루스 후보 1,142(raw 185, LZ77 957).
   - **컷신 바이트코드는 포인터를 비정렬로 둔다.** 오프닝 장면 아카이브 `0x7B083C` 는 `0x8C577` 의
     비정렬 포인터로만 닿는다. 정렬 워드만 보면 227개를 놓친다.
   - LZ77 해제 결과 앞 4바이트는 크기 머리(`u32>>8 == 해제 길이`)일 수 있다(→ 경계표는 +4).
   - **표의 마지막 값은 마지막 스크립트의 시작이지 끝이 아니다.** 압축은 해제본 전체가 페이로드,
     raw 는 다음 후보까지 창을 해독한 뒤 마지막 스크립트를 첫 종료 명령(`end/startBBS/startShop/startWarp/
     waitHold`, `continue` 아닌 `jump`)에서 자르고, 재인코딩이 ROM 과 다르면 빈 끝 스크립트로 물러선다.
2. `tools/decode_archives.py` — TextPet(exe5)으로 해독하고 **TPL→MSG 바이트 왕복**을 증명(40개 묶음, 실패 시 하나씩).
   블루스 1,121 / 컬로넬 1,126 통과. 왕복을 막던 TextPet 문제 두 가지는 고쳤다:
   - `[Extension]` 명령이 재인코딩 때 부모 base 로 돌아감(`FA 03 00 01`→`FA 02 00 01`) →
     `tools/patch_plugins.py` 가 확장 11개를 독립 명령으로 펼침, `printFolderName.entry` 4→8비트.
     원본은 `external/textpet-plugins-pristine/*.orig`.
   - 줄바꿈으로 시작하는 문자열을 `"""` 블록으로 쓰면 읽을 때 앞 줄바꿈이 사라짐 → 따옴표 문자열로 정규화.
3. `tools/classify_archives.py` → `analysis/population_{blues,colonel}.json`.
   텍스트 아카이브 = 왕복 통과 + 데이터 영역(≥`0x1C0000`) + TPL 에 해독 불가 바이트 없음.

## 대사 렌더 경로

- 부팅 복사: ROM `0x1C7A00` → IWRAM `0x03005C00`(Blues `0x1C58` / Colonel `0x1C5C` 바이트).
- 대사 글꼴 Blues `0x6D7B5C` / Colonel `0x6D8FF0`: **4bpp 16×12, 0x60 바이트/글리프**, 배경 0·잉크 1·AA 3, 그림자 없음.
  폭 표 Blues `0x425C0` / Colonel `0x425C8`(u32). 인덱스는 단일 `00..E3`, `E4 xx`→`0xE4+xx`(최대 0x1E3).
- 대사 비트맵 버퍼 `0x0200C900`: 폭 192px·4bpp(행 0x60 바이트) × **40행**, 줄 간격 14행.
  바로 뒤 `0x0200D800` 이 OBJ 타일 스테이징(960바이트 → VRAM `0x06015700`).
- 출력기 IWRAM `0x03007198`(Colonel `0x0300719C`): r1=글리프, r6=비트 단위 x, r5=문맥(+0x70 누적폭, +0x7C x).
  **행 루프 카운터가 방금 읽은 폭 값이다(폭+1 행을 그림).** 일본어 폭 11 → 12행.
- 제어 표(E5..FF): Blues `0x3F83C` / Colonel `0x3F840`. 모드 표 `[r5+0x11]`: 0=즉시 표시 루프(`0x3EACC`),
  1=한 글자씩 루프(`0x3E9C0`) — 둘 다 같은 제어 표를 쓴다. **문자열 출력 명령은 `FA`**(에그제4의 F9 자리),
  FA 처리기는 하위 번호를 범위 검사 없이 표 인덱스로 쓴다.

## 대사 한글 확장 (가시성 PoC 통과)

`tools/build_dialogue_poc.py --version {blues,colonel} --font Galmuri11.bdf --translation translations/poc_opening.json`

- **`FA FC lo hi`** = U+AC00+음절 번호 한 글자. 글리프 인덱스 = 484 + 번호.
  글꼴 보기 = 원본 484레코드(바이트 그대로) + 한글 11,172, 폭 보기 = 원본 484 + 한글 12. 출력기 리터럴 4곳을 새 보기로.
- **`FA FD a0..a3`** = 스크립트 스트림을 그 주소로 점프.
- FA 처리기: 두 루프 각각에서 원본 `E4` 경로와 같은 순서(플래그·대기·효과음·그리기·입 모양/제어 마무리)를 밟고
  그 루프의 연속 지점으로 돌아간다. 다른 FA 하위 명령은 원본 처리기로.
- **한글 전용 출력기 사본**(ROM): 원본 출력기를 다시 조립하되 행 수만 12로 고정. 폭 12 그대로 원본을 쓰면
  13행을 그려, 3줄째의 13번째 행(비트맵 40행)이 스테이징 첫 타일(=1줄 첫 칸)을 덮었다.
  빌드가 사본과 원본을 명령 단위로 대조한다(pc 상대 로드는 읽는 값으로).
- **압축 아카이브는 고정 RAM 슬롯에 풀린다**(오프닝 `0x7B083C` 184바이트 @ `0x0203E000`, 바로 뒤가 대사창 타일맵).
  번역 본문은 ROM 에 통째로 두고, RAM 사본은 바뀐 스크립트만 `FA FD <ROM>` 6바이트로 바꾼다.
  게이트: RAM 사본이 원본보다 크면 빌드 실패(오프닝 184→16, 넷토 방 613→154, 회상 2,750→2,082).
- 게이트: 입력 해시, 함수 서명 16개, 예상 바이트, Thumb-1 조립/역조립 왕복, 원본 TPL→MSG 동일,
  번역 안 한 스크립트 바이트 동일, 재해독 문자열 일치, 자모 거부, Expected Write 원장 vs 전체 차분.
